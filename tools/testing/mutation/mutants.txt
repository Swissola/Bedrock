# Mutants for tools/testing/run-mutation-tests.sh.
#
# A mutant is one small, deliberate break in a script (flip a condition, drop a line, change a
# number). The suite for that script is then run against the broken copy, and it must FAIL:
# if it still passes, the suite is not really checking that behaviour (a "survivor").
#
# One mutant per line, five fields (and an optional sixth) separated by @@ (not | or tab, which the expressions use):
#
#   hook @@ name @@ target file (relative to the repo root) @@ sed expression @@ what it breaks [@@ tag]
#
# The only tag is `not-observable-on-windows`: the mutant changes something (such as a file's
# executable bit) that Windows Git Bash cannot observe, because it reports any file starting with
# `#!` as executable. On Windows the runner reports such a mutant as skipped, not as a survivor;
# on Linux and macOS (CI) it runs normally.
#
# `hook` is the group name used by --hook, and picks the suite: tools/hook-templates/test-<hook>.sh
# or, failing that, tools/test-<hook>.sh. The sed expression is applied (default sed, so basic
# regular expressions) to a COPY of the target; the repo itself is never modified. A line whose
# expression changes nothing is reported as a broken mutant, so a refactor that moves the
# target text cannot silently turn a mutant into a no-op. Blank lines and # lines are ignored.
# Check them without running any suite: bash tools/testing/run-mutation-tests.sh --check-applies
